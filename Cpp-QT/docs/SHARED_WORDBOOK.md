# C# 与三平台 Qt 共享词库

本说明适用于本次支持公共载荷的共享版本。Windows C#、Windows Qt、macOS Qt、Linux Qt 通过同一个 Gitee SSH 数据仓库交换词条来源、收藏和删除事件。固定标签 `v1.5.1` 的旧程序不支持新的公共 JSON 格式，需要升级后才能参与双向共享。

## 1. 同一个人使用同一词库身份

各设备手动配置以下两项为相同的值：

| 字段 | 共享约定 |
| --- | --- |
| 根级 `username` | 同一个人填写同一固定身份；不同人填写不同身份。不是 Gitee 登录名，也不会由 SSH 自动识别。 |
| `CacheSync.Repository` | 同一 Gitee SSH 词库仓库地址；每个设备的本机 SSH 身份都具有该仓库的读写权限。 |

默认 `username` 留空会生成本机隔离身份，不保证各系统相同。这是首次运行的隔离措施，不是跨平台账号登录。需要共享时，主动填入自己的固定值，例如自己选定的 `yf-personal`；仅允许 1–64 位小写字母、数字、下划线或连字符，并避开系统保留名。

参考 [`configs/shared-user.example.json`](../configs/shared-user.example.json)。其中 `your-user` 是必须替换的占位值，此文件不会被程序自动加载。建议将需要的字段合并到本机已有设置，保留各设备的其他设置。

以下字段按设备分别维护：

| 字段 | 本机约定 |
| --- | --- |
| `CacheSync.DeviceId` | 新设备首次配置时留空，让程序生成该设备的固定种子；已有设备保持原值。不要复制其他设备已生成的值，不要每次启动都重置。 |
| `CacheSync.PrivateKeyPath` | 当前系统自己的 SSH 私钥路径，或留空使用该系统的 SSH 默认配置/agent。不要在设备间传递私钥，也不把私钥提交到词库仓库。 |
| `CacheSync.KnownHostsPath` | 当前系统已核验的 `known_hosts`，或留空使用本机默认位置。首次使用前核验 Gitee 主机密钥。 |
| `ApiKey`、`DeepSeek.ApiKey` | 仅在需要联网查询的本机配置。浏览同步得到的释义不需要开启 DeepSeek，也不需要调用 API。 |
| 字体、样式和窗口位置 | 保留适合该操作系统的本机设置，不随词库同步。 |

Windows、macOS 和 Linux 的路径不同，不能把某台机器完整的真实 `settings.json` 原样公开或当作所有机器的设置。旧 C# `ProtectedApiKey` 由 Windows 当前用户保护，Qt 不解密它；有需要时在本机重新填写明文 `ApiKey`。

## 2. 本地数据库与公共分片

本次共享客户端的本地库为：

```text
<data-directory>/profiles/<username>/words-shared.sqlite
```

C# 使用程序所在的数据目录；Qt 在 Windows 默认使用程序目录，macOS/Linux 默认使用系统用户数据目录，也可通过 `--data-dir` 指定。各应用和设备可保留独立的本地数据目录，通过 Gitee 合并；不需要将数据库放到同一网络磁盘上。

Gitee 数据仓库中的公共快照为：

```text
users/
└─ <username>/
   └─ shared/
      ├─ cs-<device-hash>.sqlite
      └─ qt-<device-hash>.sqlite
```

每个客户端只写自己的设备分片。`cs` 和 `qt` 是写入客户端的标识，不是两套数据格式；C# 与 Qt 都读取这个公共目录。两种 Qt 架构及三个操作系统不需要单独的用户目录。

同步采用 SQLite 快照和词条级合并，不让 Git 对二进制 SQLite 文件做内容合并。一个词按规范化词头和中英方向确定身份，词下可以保留多个来源。来源查询时间决定新旧；收藏/取消收藏事件和删除标记分别比较时间。摘要优先使用 DeepSeek；重新查询后的完整正文按当前选择规则展示。取消收藏与移除都能传播，旧快照不会直接把较新的删除状态覆盖掉。

查询历史、导航位置和导入错误属于本地状态，不在设备之间合并。设置、API Key、SSH 文件、字体和窗口状态均不是同步内容。

## 3. 从现有数据升级

### 已有 C# 词库

1. 保留原设置、`profiles/` 目录和 `words.sqlite`。用本次共享版本升级原客户端；不要拿固定旧版 `v1.5.1` 代替本次共享构建。C# 构建和部署说明见 [仓库 README](../../README.md)。
2. 确认本机 `username` 与原词库一致。需要另一设备加入时，在另一设备填写相同的值；不要通过直接改 SQLite 内部用户字段来合并不同人的库。
3. 在新版 C# 中执行一次“同步”。新版 C# 兼容读取旧 GZip/.NET 二进制 XML、旧 Qt JSON 和公共 JSON，并把可共享内容发布为公共快照。旧本地库和旧远端快照保留。
4. 其他设备使用共享版 Qt，配置相同用户身份、仓库及各自 SSH 权限后同步。它们即可读取公共快照，以后的查询、收藏和删除也会传回新版 C#。

Qt 无法直接解码旧 .NET 二进制 XML。若公共目录尚无对应释义，应先让持有旧数据的新版 C# 成功同步一次。仅在无法运行新版 C# 的离线搬运场景下，才需要 [`Export-Legacy.ps1`](../tools/Export-Legacy.ps1) 和 `MyDictTool --import-json`；常规双向共享不要求反复手工导出。

### 已有 Qt 词库

本次 Qt 启动先显示窗口，随后在后台初始化 `words-shared.sqlite`，只读导入相邻的旧 `words-qt.sqlite`。本地历史和导入错误只搬入一次，迁移标记避免重复启动重复搬运。旧库保留，不会被改写为公共格式。

同步还兼容读取旧 `qt-users/<username>/` JSON 载荷快照，以及旧 `users/<username>/` 下直接存放的兼容 JSON 快照。旧 C# 二进制内容仍由新版 C# 转成公共快照。旧分片不删除，新内容统一写到 `shared/`。

首次迁移量大时，后台需要一定时间；窗口可继续移动、缩放和切换页面，正在初始化的词库操作会等数据库就绪。无需为了“清理旧格式”先删除旧库或远端快照。

## 4. 日常同步

- 先在每台设备完成 Git/SSH 配置，再把 `CacheSync.Enabled` 设为 `true`。
- 启动时自动拉取；首次本地变更后约 30 分钟批量同步；顶部“同步”按钮可立即执行。
- 本地查询和收藏通过 SQLite 事务立即保存。网络失败不会撤销已提交的本地内容，稍后可重试。
- 关闭窗口会取消网络同步，并确保已开始的本地写入完成；不靠关闭时等待一次远程推送来保存词库。
- 在设置中切换 `username` 会切换本地用户词库，不会自动合并原用户的数据；不要把切换用户当作重命名词库的方法。

API 密钥不参与共享。可以在一台设备查询 DeepSeek，再在其他设备同步浏览结果；其他设备保持 DeepSeek 关闭即可。

## 5. 格式约定

公共 SQLite 元数据：

```text
schema = 1
payload_format = mydict-json-v1
```

每个来源的 `payload` BLOB 由以下部分组成：

```text
ASCII "MYDICT-JSON1\n" + UTF-8 compact JSON Entry
```

`Entry` 及内部 DTO 使用一致的 PascalCase 字段名，例如 `Word`、`Pair`、`Summary`、`Record`、`Meanings`、`Senses`、`Definition`、`Chinese`。编码不使用 GZip；公共写入使用稳定的紧凑 JSON 键排序，避免相同查询时间下因语言编码差异不断互相覆盖。

查询时间和删除时间沿用 .NET UTC ticks：从公元 1 年开始计数，每 tick 为 100 纳秒，不是 Unix 时间戳。收藏事件采用统一 UTC 文本。协议版本与产品版本是两套概念：相同界面版本号不代表旧可执行文件已具备公共载荷支持。

旧 `qt-json-v1`/`MYDICT-QT-JSON1\n` 和无公共标记的 C# GZip 二进制 XML 是兼容读取格式。新内容只写公共格式。固定旧版不能可靠读取公共 BLOB，所以新分片使用独立的 `shared/` 子目录保护旧数据；请升级客户端，不要移动公共分片到旧版直接扫描的目录。

## 6. 排查“设备之间看不到同一个词库”

| 现象 | 检查项目 |
| --- | --- |
| 同步成功但单词不同 | 各端实际 `username` 是否完全相同、是否连接同一数据仓库；默认生成的本机身份通常不同。 |
| Qt 看不到旧 C# 释义 | 原数据是否仍仅在旧二进制快照中；先用共享版 C# 成功同步一次，确认 `users/<username>/shared/cs-*.sqlite` 已发布。 |
| 收藏/删除只在一端生效 | 所有活跃客户端是否都是支持公共载荷的共享版，是否有一端仍运行固定旧版。 |
| 另一系统 SSH 失败 | 检查该设备自己的 Git/SSH、私钥权限、主机信任和本机路径；不用复制另一设备的私钥来修复。 |
| 换 `username` 后词库空 | 这是另一个独立身份；恢复原值查看原库，不删除旧文件或直接改数据库用户字段。 |
| 某端 DeepSeek 未配置 | 不影响同步和阅读已有结果；只有该端发起新的 API 查询时才需要本机密钥。 |

如需进一步排查，保留原库和旧快照，先在副本上验证。不要把真实 SQLite、导出文件、设置或私钥提交到源码仓库或问题附件。

## 7. 完成接入后的检查

1. 在新版 C# 中选择一个已有词条，收藏并同步。在 Windows、macOS、Linux Qt 中分别同步，确认词头、摘要、释义来源和收藏状态一致。
2. 在其中一个 Qt 客户端取消收藏并同步，再在其他客户端同步，确认取消状态传播。使用已有词条即可，不需要调用付费 API。
3. 对一个用于验证的未收藏词执行 X 移除并同步，再从其他客户端拉取，确认该词消失。再次同步旧快照不应让它复活；重新主动查询则可以生成新的结果。
4. 核对每台设备仍使用自己的 SSH 路径、`DeviceId`、API 密钥、字体和窗口位置。同步词库不会覆盖这些设置。
5. 确认旧 `words.sqlite`、`words-qt.sqlite` 和远端旧快照仍保留，公共分片位于 `users/<username>/shared/`，没有为了升级删除或覆盖原文件。
